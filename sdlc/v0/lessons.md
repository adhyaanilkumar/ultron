# Lessons from building V0 with ultron's own pipeline

We build V0 by playing ultron's pipeline with Claude Code subagents: the main session plays the engine, and
subagents play the ultron agents at their spec settings. Each lesson below is something ultron itself must handle.
Lessons that change approved V0 behaviour go to the owner first. The rest feed the next cycle's `intent.md` (Maintain).

| # | Date | What happened | Lesson for ultron | Where it lands |
|---|---|---|---|---|
| L1 | 2026-11-10 | T35's mascot passed 80 tests, but the owner saw it was asymmetric. Cause: a transparent cell prints a space while the previous cell's background colour is still set, so the space shows as a coloured block. The testing agent decoded each cell as if colours reset between cells. A real terminal doesn't do that. | (1) The testing agent must judge output the way the real consumer does: for terminal output, decode ANSI with state carried over, or take a screenshot. (2) **Visual acceptance criteria need a visual check.** The decomposition agent should name the tool a criterion needs (a screenshot through Claude in Chrome or computer use, or a terminal emulator library). tasks.md has no field for that today. | Next cycle: add a `verify_with` field per criterion (FR5). V0: T35's retry and the T48 demo |
| L2 | 2026-11-10 | The owner found T35's defect at the `result` gate, after both agents passed it. | The human result gate catches what agent tests miss, especially look and feel. Keep `result` human by default (§8). An `unattended` preset should warn that visual criteria go unchecked. | Confirms §8. Next cycle: warn on `unattended` when tasks have visual criteria |
| L3 | 2026-11-10 | At T35's `result` gate the owner sent the work back two stages, to **decomposition**, to add `verify_with` and `mcp`. Eight tasks already had code. The spec has no rule for this: gates only offer approve, changes (to the same stage) or reject. | **A human at any gate can send work back to any earlier stage** (intake, spec, decomposition, plan), with a comment. The engine reruns that stage's agent with the comment. Every downstream artifact built on the old one is marked **stale**, and each affected task reruns plan → code → test from the new artifact. Existing code is kept as the starting point, not thrown away. The rerun isn't a failed attempt and doesn't climb a rung. Merged tasks reopen too. The engine shows which tasks are affected, and what it will cost, before rerunning. | Next cycle: a "send back to stage" option on every gate form, stale-marking in the event log, a dependency-aware rerun. Recorded in `sdlc/backlog.md` |
| L4 | 2026-11-11 | Merging `v0-design` into the T05 and T06 worktrees conflicted on `decisions.md`: each task branch had appended its own gate rows, and so had `v0-design`. The fix was to keep both sides. | The gate log must not live as one shared file edited on many branches. ultron keeps decisions in the engine's own state (`ultron/state`, event log), never in task branches, so merges can't conflict on it. | Confirms spec: decisions in engine state. Self-build: only the main session writes `decisions.md`, on `v0-design` |
| L5 | 2026-11-11 | In the T03 and T04 reruns, `make test` from PowerShell fails 5–6 of T01's nested acceptance tests (they spawn `make` from inside pytest; `[WinError 2]` file not found). Plain `uv run pytest` passes everything. Two developers spent turns on it, and one reported it as a risk in its own task. | Tests that spawn the build tool from inside the build tool are fragile across shells. ultron's engine must run the target's contract commands itself, in one known shell, and must tell agents which failures belong to another task instead of letting each rediscover them. | Self-build: fix in T01's rerun. Next cycle: engine-owned contract run with per-task failure attribution |
| L6 | 2026-11-11 | Merging T02 and T03 made `findings.md` conflict (each added its own section), and `uv.lock` conflicted on every merge that changed dependencies. After the merge, T02's own test failed: it read everything after `## Host` to the end of the file, so T03's rows counted. Each task passed alone; only the merge broke it. | (1) The engine regenerates lockfiles on merge instead of hand-merging them. (2) Tasks that share an artifact file need a fixed section layout. (3) The engine reruns the full test suite after **each** merge, in dependency order, before the next merge, and a post-merge failure goes back to the owning task. | Next cycle: lockfile regeneration in the merge step; post-merge test run per merge (FR merge gate). Self-build: Local section placed first in `findings.md` |
| L7 | 2026-11-11 | T13's developer needed model prices the spec doesn't give, so it silently used the previous generation's. The engine caught it only by reading the report. | Agents fill gaps in reference data with plausible guesses. ultron must hand agents the facts they need (prices, model ids, project keys) from config or a dated reference file, and the testing agent must check against that source, not the developer's numbers. | Next cycle: a dated reference-data file the engine injects into prompts |
| L8 | 2026-11-11 | The owner moved Jira testing from AD to AK while T25's developer was running. The message reached it only after it had already read AD (read-only; the data was then discarded). | A message to a running agent arrives late. Rules that limit what an agent may touch (which project, which board) must be in config the agent's tools enforce before it starts, not sent mid-run. A changed rule should stop and restart the affected agents. | Next cycle: per-repo allowlists enforced in tools; a settings change marks running attempts stale |
| L9 | 2026-11-11 | Several tasks invented shared names on their own: T08 chose the event names that drive state, T05 left the lock path to the caller, T11 chose `ready()` semantics. Later tasks must match them, but nothing records them as a contract. | When the spec is silent on an interface, the first task to define it should publish it in a shared contracts file, and the decomposition agent should flag such gaps up front. Later tasks' testing agents check against it. | Next cycle: `contracts.md` per requirement; decomposition flags undefined interfaces |
| L10 | 2026-11-11 | Agents ran checks from different shells (Bash tool vs PowerShell, PATH appended vs prepended) and got different results for the same code; one T05 multi-process test failed once under load and then passed. | Only the engine's own contract run, in one fixed shell, counts. Agent-reported results are advisory. A test that fails then passes on rerun is recorded as flaky, not ignored. | Confirms L5. Next cycle: flaky-test record in the event log |
| L11 | 2026-11-11 | T06 attempt 3 (R5) and T25's attempt-2 tester hit the Pro 5-hour limit mid-run. The engine resumed both agents' saved sessions with a message, and they continued from where they stopped. | Rerunning an attempt in a fresh session repeats its most expensive part. ultron should store each attempt's session id and reopen it after a usage limit, falling back to a rerun only if that fails. | Backlog: "Resume an agent's session after a usage limit" |
| L12 | 2026-11-11 | After T06's developer was resumed from the usage-limit stop, its edit tool had forgotten which files it had read and refused edits until it re-read them. | A resumed session isn't fully the same as an uninterrupted one: tool-side state can be lost. ultron's resume (backlog item) must tell the agent it was resumed and that it may need to re-read files, and must not count the extra reads as a fault. | Adds to the backlog item "Resume an agent's session after a usage limit" |
| L13 | 2026-11-11 | Three times (T35 and T09 testing agents, T10 developer) an empty `tests/acceptance/test_tNN.py` appeared in the main repo instead of the agent's worktree, from a PowerShell command run in the wrong folder. The second one blocked a merge. | Agents must not be able to write outside their worktree. ultron should run each agent with its working folder locked to the worktree (tool-level path guard), and the engine should check the main checkout is clean before every merge. | Next cycle: path guard per agent; pre-merge clean check |
