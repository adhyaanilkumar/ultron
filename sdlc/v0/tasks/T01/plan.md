## Risks
1. **`make` on `windows-latest` isn't guaranteed.** The CI Windows step installs it explicitly. Verified only by the
   first PR run.
2. **Local PowerShell has neither `make` nor `uv` on PATH.** Each session prepends `C:\msys64\usr\bin` and
   `C:\Users\Anil Kumar ML\.local\bin`. The path has spaces, so the PATH entry is set through `$env:Path`, not inline.
   The Makefile must not hard-code `uv`'s location.
3. **MSYS2 `sh` and the Windows PATH.** Recipes run under MSYS2 `sh`. A failed PATH conversion would show up as
   "uv: not found" in `make build`. Caught by the first run.
4. **Pytest exit code 5.** With no tests collected, pytest exits 5 and `make test` fails. T01 has tests in all four
   files, so this is avoided.
5. **Lock drift.** `uv.lock` is generated on Windows. The lock is cross-platform, but CI on Linux runs
   `uv sync --locked`, so a platform-specific mismatch would show there.
6. **Name clash in later tasks.** `ultron.mcp` is a subpackage, while the MCP SDK is top-level `mcp`. Absolute
   imports keep them apart. Noted for T20-era work, nothing to do now.
7. **Mypy strict on empty packages.** Only `__init__.py` files and `cli.py` are checked, so the risk is low.
8. **Dependency choices** (pytest, ruff, mypy, PyYAML) are picked at lock time. Their versions are recorded in
   `uv.lock`, so the build is reproducible.
